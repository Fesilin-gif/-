# Портфолио — личный сайт

Третье, самостоятельное приложение репозитория. Соседние проекты
(PCMarket в корне и `project-amb/`) оно не трогает: свои зависимости,
своя сборка, свои изображения — всё внутри `portfolio/`.

Next.js 15 (App Router) · React 19 · TypeScript. Без GSAP, Lenis, видео
и 3D: сцена держится на одном слушателе прокрутки и CSS `transform`.

## Запуск

```bash
cd portfolio
npm install
npm run dev      # http://localhost:3001
npm run build
npm start
npm run lint     # tsc --noEmit
```

Порт 3001 — чтобы можно было поднимать одновременно с соседними
приложениями, которые заняли 3000.

## Что происходит на экране

1. Панорама на весь экран. Никакой рамки арки, никаких карточек поверх.
2. При прокрутке камера отъезжает: панорама уменьшается и уходит за
   арку. Вокруг проступает белое поле.
3. В проёме арки открывается вид — тот же пейзаж, но обрезанный точно
   по форме окна: камень и девушка его закрывают собой, ничего не
   торчит за краями и не видно сквозь прозрачное поле вокруг арки.
4. Композиция собирается: заголовок «Какой ваш выбор?» над аркой,
   ряд медальонов под ней.
5. Наведение на медальон — короткий подъём и свет, 180 мс, и всё.
   На телефоне выбор работает нажатием. Выбор медальона уже переключает
   вид в проёме (пока свой кадр не задан ни у одного проекта — значит,
   переключать пока не на что, см. «Смена пейзажа в проёме» ниже).

## Как устроен переход

Прокрутка ведёт сцену напрямую: высокий блок `.scene` задаёт длину
хода, внутри него залипает экран `.stage`, а положение страницы внутри
блока — единственный источник прогресса. Ничего не «проигрывается»,
поэтому назад сцена идёт ровно тем же путём и останавливается там, где
её остановили — реверс проверен programmatically (скролл вперёд и назад
по одним и тем же точкам даёт идентичные кадры).

Три слоя, снизу вверх:

1. **`.layer--landscape`** — свободная панорама первого экрана. Уезжает
   назад (геометрический, не линейный масштаб — темп отъезда читается
   ровным на всём пути) и тает прозрачностью, пока не скроется за аркой.
   Растушёвка краёв идёт раньше прозрачности: как только кадр отрывается
   от границ экрана, мягкий край не даёт ему читаться вырезкой.
2. **`.window`** — вид в проёме. Тот же файл панорамы, но как CSS-фон
   (`background-size: cover` + `background-position` по точке интереса),
   обрезанный точной маской проёма (`arch-opening-mask.png`) — маска
   получена из альфа-канала самой арки, поэтому проём и силуэт девушки
   в ней совпадают с рисунком пиксель в пиксель.
3. **фигура арки** (`arch-transparent.png`) — камень и девушка,
   непрозрачные; проём и поле вокруг — прозрачные. Здесь ничего не
   нарисовано внутри окна: то, что видно в проёме, — целиком слой 2.

Слои 2 и 3 — родные дети одного контейнера (`.layer--arch`) с ОДНИМ
`transform` на двоих: масштаб и положение считает `ArchScene.tsx` один
раз за кадр и применяет к контейнеру, а маска и передний план просто
заполняют его на 100% ширины/высоты. Поэтому окно и арка никогда не
могут разъехаться — на любом экране, на любом шаге прокрутки.

Стык между панорамой и видом в проёме короткий и мягкий: у обоих
одна и та же точка обрезки (`LANDSCAPE.anchor` в `lib/scene.ts`) и одна
и та же формула кадрирования (`fitCoverFocused` — специально повторяет
формулу CSS `background-position`, а не придумывает свою), поэтому в
момент, когда свободная панорама гаснет, а вид в проёме проявляется,
кадр не «прыгает» — обе картинки показывают один и тот же кроп.

Экран измеряется у самих блоков через `ResizeObserver`, а не у
`window`: изменение высоты браузера на телефоне, поворот экрана и
подгрузка шрифтов пересобирают раскладку, а не ломают её. Высоты — в
`svh`. Кадры вписываются целиком: девушка и арка не обрезаются никогда.

При `prefers-reduced-motion: reduce` (и просто без JS) сцены нет:
синхронный скрипт в `<head>` не ставит класс `.js`, и страница
раскладывается обычным потоком — панорама, заголовок, арка (с тем же
видом в проёме — маска работает и здесь, это чистый CSS), медальоны.
Всё видно сразу, ничего не ждёт прокрутки.

## Структура

```
app/
  layout.tsx        шрифты, метаданные, флаг движения
  page.tsx          главная — одна сцена
  globals.css       токены, сброс, типографика
  scene.css         два режима сцены, окно в проёме, медальоны
components/
  ArchScene.tsx      измерения экрана и запись в transform
  Medallions.tsx     ряд медальонов
lib/
  scene.ts           геометрия, фазы, вид в проёме — чистые функции
  projects.ts        данные проектов (пока пустые слоты)
public/media/
  landscape.webp        панорама, 1672×941
  arch-transparent.png  арка и девушка, прозрачный проём и поле,
                         1122×1402
  arch-opening-mask.png маска проёма — сгенерирована из альфа-канала
                         arch-transparent.png, в код не редактируется
                         руками (см. ниже, как пересобрать)
```

## Что заполнить

1. **Проекты** — `lib/projects.ts`, массив `PROJECTS`. Сейчас там три
   пустых слота: ни названий, ни описаний, ни ссылок не придумано.
   У каждого проекта есть `id` (он же будущий сегмент адреса кейса),
   `title`, `summary`, `caseHref`, `liveHref`, необязательный
   `medallion` (кадр внутри круга) и необязательный `windowView` (см.
   ниже). Пока `caseHref === null`, медальон остаётся кнопкой выбора и
   никуда не ведёт; появится адрес — станет ссылкой, разметку менять
   не придётся. Добавить проект — добавить объект в массив, раскладка
   пересчитается сама (комфортный ряд — от трёх до шести).
2. **Кейсы** — страницы `app/case/[id]/page.tsx` по `id` из списка.
3. **Метаданные** — `app/layout.tsx`: имя, описание, домен. Там сейчас
   нейтральная заглушка без выдуманного названия.

## Смена пейзажа в проёме

Инфраструктура готова и подключена: у `Project` в `lib/projects.ts`
есть поле `windowView?: { src: string; focus?: { x: number; y: number } }`.
Не задано (сегодня — ни у одного проекта) — в проёме остаётся вид по
умолчанию, тот же `landscape.webp`. Выбор медальона уже переключает
вид (`windowViewFor` в `lib/projects.ts` → `ArchScene.tsx`), менять
код не понадобится — только вписать `windowView` нужному проекту:

```ts
{ id: 'slot-01', /* …остальные поля… */,
  windowView: { src: '/media/slot-01-view.jpg', focus: { x: 0.6, y: 0.4 } } }
```

`focus` — точка интереса от 0 до 1 (как `background-position`): за что
кадрирование держится при обрезке под форму окна. Не задана — обрезка
идёт от центра. Классифицировать «свадьбы», «детские» и «события» как
разделы портфолио не стал — этого не было в списке моих сайтов.

Файл кладите в `public/media/`, размер и пропорции — любые: `background-size: cover`
обрежет под форму проёма сам.

### Если понадобится пересобрать маску проёма

`arch-opening-mask.png` не рисуется руками — это результат обработки
альфа-канала `arch-transparent.png` (топологически замкнутая
прозрачная область внутри непрозрачного силуэта арки и девушки, самая
крупная по площади — так отсеивается шум вроде мелких просветов в
волосах). Пересобирать нужно только если появится новый файл арки.
Метод (Python, Pillow + SciPy):

```python
from PIL import Image
import numpy as np
from scipy.ndimage import binary_fill_holes, label

alpha = np.asarray(Image.open('arch-transparent.png'))[:, :, 3]
opaque = alpha > 10
holes = binary_fill_holes(opaque) & ~opaque
labels, _ = label(holes)
sizes = np.bincount(labels.ravel()); sizes[0] = 0
window = labels == np.argmax(sizes)

out = np.zeros((*alpha.shape, 4), dtype=np.uint8)
out[..., :3] = 255
out[..., 3] = np.where(window, 255 - alpha, 0)  # мягкий край антиалиасинга арки
Image.fromarray(out, 'RGBA').save('arch-opening-mask.png')
```

И заодно поправьте в `lib/scene.ts` константы `ARCH.content` и
`ARCH.opening` (доли ширины/высоты файла) — они измерены по тому же
альфа-каналу, но руками, отдельным разовым скриптом, не частью сборки.

## Мелочи, о которых стоит знать

- Холст намеренно не `#ffffff`, а `#fefefe` — так задано изначальными
  иллюстрациями; на итоговой композиции (прозрачный PNG поверх белого
  холста) разницу не видно, но так исторически сложилось при первой
  сборке сцены, менять без причины не стал.
- В файле арки вокруг рисунка широкие прозрачные поля (слева и справа
  по ~18%). Сцена вписывает в экран не файл, а саму живопись
  (`ARCH.content`), иначе арка выходит заметно мельче, чем могла бы.
- Полезно, но не обязательно: кадры для медальонов — квадратные, от
  240×240, по одному на проект. Пока их нет, в круге стоит номер.
