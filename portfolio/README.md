# Портфолио — личный сайт

Третье, самостоятельное приложение репозитория. Соседние проекты
(PCMarket в корне и `project-amb/`) оно не трогает: свои зависимости,
своя сборка, свои изображения — всё внутри `portfolio/`.

Next.js 15 (App Router) · React 19 · TypeScript. Без GSAP, Lenis, видео
и 3D: сцена держится на одном слушателе прокрутки и двух `transform`.

## Запуск

```bash
cd portfolio
npm install
npm run dev      # http://localhost:3001
npm run build
npm start
npm run lint     # tsc --noEmit
```

Порт 3001 — чтобы можно было поднимать одновременно с соседними
приложениями, которые заняли 3000.

## Что происходит на экране

1. Панорама на весь экран. Никакой рамки арки, никаких карточек поверх.
2. При прокрутке камера отъезжает: панорама уменьшается и садится на
   город, нарисованный в проёме арки. Вокруг проступает белое поле.
3. Композиция собирается: заголовок «Какой ваш выбор?» над аркой,
   ряд медальонов под ней.
4. Наведение на медальон — короткий подъём и свет, 180 мс, и всё.
   На телефоне выбор работает нажатием.

## Как устроен переход

Прокрутка ведёт сцену напрямую: высокий блок `.scene` задаёт длину
хода, внутри него залипает экран `.stage`, а положение страницы внутри
блока — единственный источник прогресса. Ничего не «проигрывается»,
поэтому назад сцена идёт ровно тем же путём и останавливается там, где
её остановили.

Две иллюстрации нарисованы отдельно и не совпадают пиксель в пиксель,
поэтому сцена не притворяется одной 3D-сценой. Кадры сведены по общей
опорной точке — городу на холме (`LANDSCAPE.anchor` и `ARCH.anchor` в
`lib/scene.ts`), а масштаб подобран так, чтобы город в панораме стал
размером с город в проёме. Расхождение гасят два приёма:

- растушёвка краёв панорамы — начинается рано, кадр перестаёт читаться
  вырезкой и становится живописным пятном;
- короткая перекрёстная прозрачность — арка проявляется, пока панорама
  ещё видна, без вспышки и скачка.

Слои лежат снизу вверх: панорама → арка → интерфейс. Панорама **уже**
под аркой — это и есть задел под подстановку прозрачного проёма.

Вся арифметика — в `lib/scene.ts`, чистыми функциями, без DOM. Там же
все настроечные числа: фазы `PHASE`, длина хода `SCENE_TRAVEL_VH`,
масштаб посадки `LANDSCAPE_END_WIDTH_RATIO`.

Экран измеряется у самих блоков через `ResizeObserver`, а не у `window`:
поэтому изменение высоты браузера на телефоне, поворот экрана и
подгрузка шрифтов пересобирают раскладку, а не ломают её. Высоты —
в `svh`. Кадры вписываются целиком: девушка и арка не обрезаются
никогда.

При `prefers-reduced-motion: reduce` (и просто без JS) сцены нет:
синхронный скрипт в `<head>` не ставит класс `.js`, и страница
раскладывается обычным потоком — панорама, заголовок, арка, медальоны.
Всё видно сразу, ничего не ждёт прокрутки.

## Структура

```
app/
  layout.tsx        шрифты, метаданные, флаг движения
  page.tsx          главная — одна сцена
  globals.css       токены, сброс, типографика
  scene.css         два режима сцены и медальоны
components/
  ArchScene.tsx     измерения экрана и запись в transform
  Medallions.tsx    ряд медальонов
lib/
  scene.ts          геометрия и фазы — чистые функции
  projects.ts       данные проектов (пока пустые слоты)
public/media/
  landscape.webp    панорама, 1672×941
  arch-figure.webp  девушка в арке, 1122×1402
```

## Что заполнить

1. **Проекты** — `lib/projects.ts`, массив `PROJECTS`. Сейчас там три
   пустых слота: ни названий, ни описаний, ни ссылок не придумано.
   У каждого проекта есть `id` (он же будущий сегмент адреса кейса),
   `title`, `summary`, `caseHref`, `liveHref` и необязательный
   `medallion` — кадр внутри круга. Пока `caseHref === null`, медальон
   остаётся кнопкой выбора и никуда не ведёт; как только появится
   адрес, тот же медальон станет ссылкой, править разметку не нужно.
   Добавить проект — добавить объект в массив, раскладка пересчитается
   сама (комфортный ряд — от трёх до шести).
2. **Кейсы** — страницы `app/case/[id]/page.tsx` по `id` из списка.
3. **Метаданные** — `app/layout.tsx`: имя, описание, домен. Там сейчас
   нейтральная заглушка без выдуманного названия.

## Что нужно подготовить для настоящей смены пейзажа в арке

Сейчас файл арки непрозрачный: внутри проёма нарисован свой пейзаж, и
подменить его нельзя — прямоугольная картинка поверх готовой
иллюстрации выглядела бы наклейкой. Поэтому в сцене её нет.

Чтобы пейзаж в проёме стал сменным, нужен **один файл**:

- **Арка и девушка с прозрачным проёмом.** PNG или WebP с альфа-каналом,
  те же пропорции и та же композиция, что у нынешнего файла
  (1122×1402 или больше — пропорции важнее размера). Прозрачными должны
  быть: проём арки целиком (вместо неба, долины, реки и города —
  пустота) и поле вокруг арки. Камень, подоконник, платье и волосы
  остаются непрозрачными; волосы девушки на фоне проёма — с мягким
  краем, иначе по контуру пойдёт ореол. Тени и блики, которые пейзаж
  отбрасывает на камень, лучше оставить на камне.
- Класть в `public/media/`, например `arch-figure-cutout.png`.

Что поменяется в коде — три строки, без переделки сцены:

1. `ARCH.src` в `lib/scene.ts` — путь к новому файлу.
2. `PHASE.landscapeOut` — убрать (панорама больше не гаснет, она видна
   сквозь проём).
3. `LANDSCAPE_END_WIDTH_RATIO` — поднять примерно до `0.4`, чтобы
   панорама заполняла проём целиком. Прямоугольник проёма уже измерен
   и лежит рядом — `ARCH.opening`.

После этого внутрь проёма можно подставлять любой пейзаж, в том числе
свой для каждого выбранного медальона.

Полезно, но не обязательно:

- **Оригиналы в PNG.** В `public/media/` лежат WebP, собранные из
  присланных файлов без изменения разрешения. Если нужны исходники —
  положите их рядом и поправьте `LANDSCAPE.src` / `ARCH.src`.
- **Кадры для медальонов.** Квадратные, от 240×240, по одному на
  проект. Пока их нет, в круге стоит номер.

## Мелочи, о которых стоит знать

- Холст намеренно не `#ffffff`, а `#fefefe`: это фон присланной
  иллюстрации арки. Если поставить чистый белый, по краям кадра
  проступит светлый прямоугольник.
- В файле арки вокруг рисунка широкие белые поля (слева и справа
  по ~18%). Сцена вписывает в экран не файл, а саму живопись
  (`ARCH.content`), иначе арка выходит заметно мельче, чем могла бы.
